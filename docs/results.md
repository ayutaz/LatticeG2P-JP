## 0. 要約

```
問い 1: 辞書制約があるなら、100M 級の言語モデルを使わずに OpenJTalk を大きく上回れるか

答え:   上回れない。並ぶのが上限で、並んだのはニューラルを使わない「辞書 + 連接行列」（= MeCab + UniDic）だった。
        ・品詞を保つ辞書 + UniDic の連接行列は、実 MeCab + UniDic を 1 件単位でほぼ再現し、OpenJTalk と区別できない
          （公式の物差しで Accuracy 96.73 vs 96.63）
        ・そこにニューラル経路選択（生成データ 6,554 文で学習）を足すと、対象語は下がる（−0.79 pt、seed 3 本とも）
        ・軽量なニューラル構成（連接行列なし）は OpenJTalk に 2.93 pt 負ける

問い 2: それは実用的な CPU レイテンシに収まるか

答え:   収まる（91 字 p50 2.59〜2.85 ms・1 スレッド）。ただし OpenJTalk（0.17 ms）より 1 桁遅い
```

**OpenJTalk との差の正体は、大規模コーパスから学ばれた連接コスト（UniDic の連接行列）と、それを引くための品詞だった。**
データ量（4 倍）・パラメータ数（6 倍）・事前学習エンコーダのどれでも差は縮まらなかった。

## 3. OpenJTalk との差の正体

| 仮説 | 検証 | 結果 |
|---|---|---|
| データ量 | 1.3 倍 / 4 倍（語彙 8 倍） | ✗ +0.95 pt |
| パラメータ数 | 2.07 → 12.69M（6.1 倍） | ✗ 平坦（→ §5） |
| 事前学習エンコーダ | 文字単位 DeBERTa tiny | ✗ 辞書事前分布が利得を吸収（+4.77 → +0.52 pt・判定不能） |
| 遷移項（低ランク近似） | 16 / 32 次元 × seed 3 本 | ✗ 検出できず（+0.07 pt / SE 0.28） |
| **遷移項（連接行列そのもの）** | 固定の行列を差し込む・決定的 | **✓ +1.40 pt（seed 3 本とも）** |
| **品詞（辞書の重複排除で失っていた）** | 品詞を保つ辞書 | **✓ U → U_pos で +1.22 pt**（U と実 MeCab の差 1.18 pt をほぼ埋めた） |

```
N0     94.30   ニューラル（軽量）
 + 連接行列     →  N      95.70
 + 品詞を保つ   →  N_pos  96.35   ← ここで U_pos（97.05）を下回る
U_pos  97.05   辞書 + 連接行列（ニューラルなし）≈ 実 MeCab 97.01 ≈ OpenJTalk 96.85
（自前の物差し）
```

★**1 語の読みを選ぶ能力の大部分は、大規模コーパスから学ばれた連接コスト（と、それを引くための品詞）にあった。**
生成データ 6,554 文から学ぶニューラルは、それを置き換えられなかった。

### 品詞を保つと MeCab になる

| 対象語の正誤 | 13,536 件中 **13,528 件** |
| 対象語の読み | 13,524 件 |
| 文一致（kana 形で組み立てた実 MeCab） | 30.27% vs 30.26% |

ラティス + CRF + 連接行列は、品詞を保てば MeCab そのものになる（[R-27](pitfalls.md#r-27)）。

## 4. どこで効いたか

読みの区分別（対象語・自前の物差し）:

| | 訓読み 6,108 | 音読み 7,056 | 熟字訓・当て字 372 |
|---|---|---|---|
| U | 94.17 | 97.76 | 86.29 |
| N0（3 本平均） | 91.99 | 96.96 | 81.72 |
| N（3 本平均） | 94.28 | 97.58 | 83.33 |
| 実 MeCab | **96.32** | **98.10** | 87.63 |
| OpenJTalk | 96.04 | 97.79 | **92.47** |

- 連接行列の効果は**訓読みに集中した**（N0 → N で +2.29 pt）。直った例は `故 → ユエ`・`後 → アト`・`光 → ヒカリ`・`湖 → ミズウミ` など、隣の語との整合で決まる読み
- 熟字訓は OpenJTalk が大きく上回る（辞書の違いと考えられる）
- 誤りのほぼ全部が**経路選択の誤り**（Oracle 失敗は 1〜3%）。正規化の不一致は 0 件

## 5. 精度・レイテンシ・サイズのカーブ

元論文は backbone のアブレーション（tiny / base）を報告しているが、レイテンシは報告していない。
同条件（学習データ・epoch・seed を固定）で、BiEncoder の `hidden` と層数だけを変えた（自前の物差し・連接行列なし）。

| 構成 | hidden × 層 | params | INT8 | 対象語 | 文一致 | 91 字 p50 | p95 |
|---|---|---|---|---|---|---|---|
| **XS** | 128 × 3 | **2.07M** | **2.9 MB** | 93.94 | 77.57 | **2.59 ms** | 3.02 ms |
| S | 192 × 4 | 4.32M | 5.2 MB | 94.29 | 78.29 | 4.20 ms | 4.63 ms |
| M | 256 × 4 | 6.97M | 7.9 MB | 93.93 | 77.44 | 5.65 ms | 6.19 ms |
| L | 320 × 6 | 12.69M | 13.9 MB | 93.35 | 77.50 | 10.21 ms | 10.68 ms |
| *UnigramScorer* | — | 0 | — | 93.59 | 24.02 | — | — |
| *OpenJTalk* | — | — | — | 96.85 | 91.93 | 0.17 ms | 0.19 ms |

- **精度はサイズにほぼ依存しない**（差はばらつき以下。[R-24](pitfalls.md#r-24)）。**レイテンシは params にほぼ比例する**
- 対象語で見たニューラルの上乗せは UnigramScorer の 1 pt 未満。**文一致では 24% → 78% と大きく効く**（文全体を正しく読むには経路選択が要る）
- 91 字の内訳（XS）は文脈エンコーダが 53%、ラティス構築が 29%

INT8 のサイズは読みエンコーダも INT8 にした値。R-26 の修正で読みエンコーダを FP32 に戻したので、現在は XS 4.15 MB（91 字 p50 2.85 ms）。

## 6. Hard Set

論文が弱点と認める領域の 761 文（→ [evaluation.md](evaluation.md#3-3-hard-set弱点領域)）。対象語・自前の物差し。

| | 人名 78 | 地名 168 | 数詞 168 | 同表記 293 |
|---|---|---|---|---|
| U_pos | 87.18 | 67.86 | 64.29 | 50.51 |
| N_pos（42 / 1337 / 2024） | 88.46 / 93.59 / 93.59 | 72.02 / 63.69 / 65.48 | 85.71 / 88.10 / 86.90 | 51.19 / 47.10 / 51.19 |
| 実 MeCab | 87.18 | 67.86 | 64.88 | 50.51 |
| OpenJTalk | 76.92 | 67.26 | **87.50** | **52.22** |

組織（54 文）は、測ったどの構成も 100% だった（既定の辞書の U・N と、実 MeCab・OpenJTalk）。

- 語レベルの Oracle は 97.3%。**「固有名詞は辞書に無いから解けない」は当たらなかった**（UniDic は人名・地名を持つ）
- 人名はどの UniDic 系の構成も OpenJTalk を上回る（`四月一日 → ワタヌキ`・`生田目 → ナバタメ`）。これは辞書の差で、ニューラルの手柄ではない
- ニューラルが明確に効くのは**狙って教えた数詞**だけ（N_pos 86〜88 vs U_pos 64）
- 1 件は人名 1.28 pt・地名 / 数詞 0.60 pt・同表記 0.34 pt なので、seed 間の差の多くは数件である

★benchmark の対象語は常用漢字の読みで数詞を含まないので、数詞の改善は benchmark では見えない。

## 8. 元論文との比較

*Dictionary-Constrained Grapheme-to-Phoneme for Unsegmented Languages from LLM-Annotated Data*
（Rui Hu, Zhenpeng Zhan, Xiaolong Lin. Baidu Inc. arXiv 2609.19805, 2026）。
原文（v2）と照合し、公式評価ツールで測り直した。

| | 論文 | このリポジトリ |
|---|---|---|
| 学習データ | LLM 注釈 234 万文 | LLM 生成 6,554 文（0.3%）+ ルビ 11,057 文 |
| 文脈エンコーダ | `ku-nlp/deberta-v2-base-japanese-char-wwm`（全パラメータを学習） | スクラッチの文字単位 Transformer（2〜13M） |
| 読みの表現 | 埋め込み（256 次元）+ 線形射影 | 小型の読みエンコーダ（読みごとにキャッシュ） |
| 遷移素性 | **意図的に省いた**（ニューラルのノードスコアラが文脈の依存を捉えられるため） | 連接行列を足すと +1.40 pt（この規模では効いた） |
| 損失 | CRF + margin（m = 2.0、λ = 0.5） | 同じ |
| Accuracy（公式） | **99.62** | N_pos 95.94 / N0 93.70（辞書 + 行列 96.73） |

- 論文のデータ量のアブレーションは 10% で 99.25%、50% で 99.52%。10% でも 23 万文で、このリポジトリの 35 倍
- 論文はコード・データ・プロンプトを公開していないので、差の原因が規模なのか実装なのかは判別できない（[R-03](pitfalls.md#r-03)）
- 論文の OpenJTalk（96.63）と MeCab（96.66）は、自前の実行で再現した

## 9. 確かな結論と、判定できなかった差

**確かな結論**（ばらつきの 3 倍以上か、学習を伴わない決定的な比較）:

| 結論 | 値 |
|---|---|
| 辞書事前分布はニューラルに効く | dev の対象語 +4.25 pt |
| 数詞 + 助数詞のデータは Hard Set の数詞に効く | +19.64 pt |
| 連接行列はニューラルに効く | +1.40 pt（seed 3 本とも正） |
| 連接行列は UnigramScorer に効く | +5.23 pt |
| 品詞を保つと辞書 + 行列が実 MeCab を再現する | 対象語の正誤 13,528 / 13,536 件一致 |
| ニューラルは辞書 + 行列（品詞を保つ）を下げる | −0.70 pt（seed 3 本とも負） |
| 辞書 + 行列（= MeCab）は OpenJTalk と並ぶ | +0.20 pt（差 / SE 1.3。区別できない） |
| 精度はモデルサイズ 2〜13M でほぼ一定 | 差がばらつき以下 |

**判定できなかった差**（1 回の実行で 0.6 pt 未満。[R-24](pitfalls.md#r-24)）: 数詞データの増量（benchmark −0.28 pt）・
ルビ事前学習（−0.06 pt）・size-s が最良（+0.36 pt）・事前学習エンコーダ（対象語 +0.52 pt。文一致の +2.66 pt は実在）・
低ランクの遷移項（初回 +0.32 pt → 反復して +0.07 pt）。

### 実用上の結論

日本語 TTS のフロントエンド（例: [piper-plus](https://github.com/ayutaz/piper-plus)）で**OpenJTalk を置き換える根拠は得られなかった。**
読みの精度で並ぶのはニューラルを使わない MeCab + UniDic で、OpenJTalk は文全体の読み（文一致 91.93%）が最も良く、速く（0.17 ms）、小さい。
このリポジトリのニューラルが明確に勝つのは人名（88〜94% vs 77%）で、補うならそこに絞るのが妥当である。

## 10. 続けるなら

ニューラル経路選択の線は閉じた（上の結論）。続けるなら、**止める条件を先に決めてから**始めること。

| 候補 | 根拠 | 止める条件 |
|---|---|---|
| **辞書 + 行列を主体にし、ニューラルを小さな補正として足す** | 試した構成はニューラル主体だった。重み付けを逆にした構成（U_pos のスコア + ε × ニューラル）は測っていない。学習は要らない（ε は dev で選ぶ） | U_pos を seed 3 本の平均で 0.6 pt 上回らなければ閉じる |
| 連接行列の圧縮 | 481 MB の行列を軽く持てるか。OpenJTalk の行列は 3.8 MB | INT8 で 10 MB を超えるなら軽量の主張を捨てる |
| 連濁 / 清音の対応を特徴にする | 1 文字違いの誤りの多くが連濁・促音便 | 連濁の誤りが半分にならなければ閉じる |
| 青空文庫のルビを 25 倍にする | 使ったのは条件を満たす作品の一部（398 作品）。ルビ事前学習は未学習の数詞の般化に効いた（46.67% → 56.67%） | 5 倍で対象語が seed 3 本の平均で 0.6 pt 動かなければ閉じる |
| 読み + アクセント型の同時推定 | UniDic はアクセント型（`aType` など）を持つ | 読みで OpenJTalk を上回れていないので前提が弱い |

| M3c | dev の監査 | 誤りの 33% が評価側（[R-19](pitfalls.md#r-19)） |
| M3d | 数詞 + 助数詞 | dev の分割の問題を発見（[R-21](pitfalls.md#r-21)） |
| M3e | 事前学習・蒸留の検討 | 事前学習の利得は辞書事前分布が吸収。蒸留しない |
| M4 | ONNX・INT8・benchmark・Hard Set | 速度とサイズは目標内、精度は OpenJTalk に届かず。比較相手の過小評価を発見（[R-22](pitfalls.md#r-22)） |
| M5 | 精度・レイテンシ・サイズのカーブ | 2〜13M で精度が平坦 |
| M6 | CRF の遷移項（低ランク） | 効果は検出できず。計測のばらつきを実測（[R-24](pitfalls.md#r-24)） |
| M7 | 連接行列そのもので上限を測る | 連接行列 +1.40 pt。ニューラルは辞書 + 行列に何も足さない |
| M7 後 | 品詞を保つ辞書・INT8 の修正・公式評価ツール | U_pos ≈ 実 MeCab。ニューラルの線を閉じた（[R-26](pitfalls.md#r-26)〜[R-28](pitfalls.md#r-28)） |

## 付録: 再現手順

学習済みモデルは同梱していない。N 系の数値を再現するには、size-m を seed 42 / 1337 / 2024 で学習し（[training.md](training.md#7-学習)）、
`checkpoints/rep-size-m-<seed>` と `models/rep-size-m-<seed>-{int8,fp32}` に置く。

```bash
# 辞書（既定 / 品詞を保つ）と連接行列
uv run python scripts/build_dict_cache.py
uv run python scripts/build_dict_cache.py --keep-pos --out data/dic_cache_pos.pkl

# U・N（既定の辞書）と U_pos・N_pos（品詞を保つ辞書）。公式評価ツールの値も出る
uv run python scripts/run_m7.py --runs rep-size-m-42 rep-size-m-1337 rep-size-m-2024 --out-dir data/results/base
uv run python scripts/run_m7.py --runs rep-size-m-42 rep-size-m-1337 rep-size-m-2024 \
  --dict-cache data/dic_cache_pos.pkl --out-dir data/results/pos

# 実 MeCab + UniDic（fugashi は依存に足さず一時的に使う）
uv run --with fugashi python scripts/run_mecab_reference.py

# OpenJTalk と UnigramScorer（学習済みモデルがあれば並べる）
uv run python scripts/compare_systems.py --onnx models/rep-size-m-42-int8
```

`run_m7.py` は dev → benchmark → Hard Set の順に測り、約 45 分かかる。
