# .claude/ — このプロジェクト固有の skills と hooks

**どちらも「このプロジェクトで実際に起きた失敗」から作っている。**
一般論ではないので、失敗が再現しなくなったら消してよい。

## skills（必要なときだけ読み込まれる）

| skill | いつ読まれるか |
|---|---|
| `measuring-differences` | 数値の差を報告・比較・判断するとき |
| `vast-training` | vast.ai で学習を回すとき |
| `generating-data` | サブエージェントでデータを作るとき |
| `auditing-evaluation` | 精度が頭打ちに見えたとき / 評価セットを作るとき |

★**`CLAUDE.md` から task 固有の詳細を移した先である。**
`CLAUDE.md` は毎ターン読まれるので、**全員が常に必要とするものだけ**を置く。

## hooks（`PreToolUse` / Bash）

`.claude/hooks/guard.py` が 3 つを見る。**判定はすべて deny で、ユーザーには確認を求めない。**

| # | 対象 | 判定 | 理由 |
|---|---|---|---|
| 1 | 素の `python` / `pip` でプロジェクトのコードや依存を扱う | **deny** | 規約（CLAUDE.md） |
| 2 | ssh 越しの CPU レイテンシ計測 | **deny** | R-13。**それらしい数字が出るので誤りに気づけない** |
| 3 | `/tmp/my_instance` に無い ID の `vastai destroy` | **deny** | 他プロジェクトのインスタンスを破棄しかけた |

★**ask を使わない。** 確認待ちで自動化が止まるほうが
損が大きい。**deny なら理由が Claude に返り、Claude が自分でコマンドを直して続行できる。**

★**1 は以前 ask だった。** コマンド文字列全体を正規表現で見ていたので、
「規約違反の語が**書いてあるだけ**」の行も引っかかった。さらに `(?<!uv run )` という
後読みで判定していたため、**`uv run --with fugashi python ...` を素の python と誤認して
ユーザーの確認待ちで止まった。**
いまはコマンドを字句解析し、**実際に実行されるコマンドの先頭だけ**を見る:

| 見ないもの | 見るもの |
|---|---|
| ヒアドキュメントの本文（Python の stdin・コミットメッセージ） | ssh / bash / sh に流し込むヒアドキュメント |
| 引用符の中の文章（`echo "..."`・`-m "..."`） | ssh の遠隔コマンド・`bash -c` / `sh -c` の引数 |
| `#` 以降のコメント | `nohup` や `FOO=1` の後ろの実際のコマンド |

★**解析できないとき（引用符の不整合など）は、1 は通し、2・3 は文字列で判定する**
（取り返しのつかないものだけ安全側に倒す）。

```bash
python3 .claude/hooks/test_guard.py    # 37 ケースの判定テスト
```

★**テストのケース文字列はテストファイル側に置いてある。**
コマンドラインに規約違反の語を書くと、フックがそのコマンドを止めてしまうため。
