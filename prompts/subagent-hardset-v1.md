# Hard Set の例文生成プロンプト v1.0

`data/batches_hard/batch_NNN.jsonl` をサブエージェントに渡すときのプロンプト。

★**これは学習データではなく評価データ（Hard Set）である。**
物差し自体が間違っていると測定の意味が無くなるので、**量より正確さ**を優先する。

対象は論文が弱点として認めている領域: 固有名詞（人名・地名・企業）・
数詞 + 助数詞・同表記異読。読みは人手で書いた表で確定済み。

---

日本語 G2P（漢字の読み推定）の**評価用**データを生成するタスクです。

# 入力
`data/batches_hard/batch_NNN.jsonl` を読んでください。
各行は `{"surface": "市場", "reading": "イチバ"}` です。

# やること

各行について、**その表記がその読みで読まれる自然な現代日本語の文を 6 文**作ってください。

★★**最重要: 文脈がその読みを一意に決めること。**

同じ表記に複数の読みがあり、表はそのうち 1 つを指定しています。
**指定された読みが自然になる文脈**を書いてください。

```
市場 / イチバ  -> 「朝の市場で新鮮な魚を買った」   ✅ 生活の場としての市場
市場 / シジョウ -> 「株式市場が大きく下落した」     ✅ 経済用語としての市場
```

どちらの読みでも成立してしまう文（例:「市場を見に行く」）は**書かないでください**。
評価データなので、読みが曖昧な文は測定を壊します。

★固有名詞（人名・地名・企業名）の場合は、**その固有名詞として使われる文脈**にしてください
（「東海林さんが来た」「枚方市に住んでいる」など）。

# 出力形式

`data/batches_hard/batch_NNN.out.jsonl` に
1 行 1 文の JSONL で書いてください。

```json
{"text": "朝の市場で新鮮な魚を買った", "reading": "アサノイチバデシンセンナサカナヲカッタ", "target_surface": "市場", "target_reading": "イチバ", "target_start": 3}
```

`target_start` は `text` の中で対象表記が始まる位置（0 始まり）。
**対象表記が文中に 2 回以上出る文は書かないでください。**

# ★読みの表記規則（最重要。ここを間違えると全部落ちます）

- すべて全角カタカナで書く
- **助詞の「は」は ワ**（「私は」→ ワタシワ）
- **助詞の「へ」は エ**（「家へ」→ イエエ）
- **助詞の「を」は ヲ**（「本を」→ ホンヲ）
- **長音は表記どおり**（「東京」は トウキョウ。トーキョー とは書かない）
- 促音「ッ」、拗音「ャュョ」、撥音「ン」を省略しない
- 空白・句読点は読みに入れない

# 禁止事項

1. **算用数字・アルファベットを使わないこと。**
2. **対象語以外の固有名詞を入れないこと**（読みが不確かになるため）。
3. 記号は句読点のみ。
4. 対象語以外に、読みが難しい語をなるべく入れないこと。
   **評価したいのは対象語であって、周辺語ではない。**

# 文の要件

- 文の長さは 10〜35 文字程度
- 対象語の出現位置を散らす（文頭・文中・文末）
- 文体と話題を多様にする

# 品質について

`reading` は機械的に検証されます（辞書ラティスで生成できるか）。
**文全体の読みを一字一句正確に**書いてください。

★**自信が持てない文は書かないでください。** 6 文に届かなくても構いません。
これは物差しです。間違った物差しは無いほうがましです。

終わったら、書き出した文の数と、**書けなかった行があればその理由**を報告してください。

---

## ★実測: haiku ではこのタスクの品質に届かない（2026-09-20）

`scripts/build_hard_set.py` の機械検証にかけた採用率:

| バッチ | モデル | 採用率 | 主な落ち方 |
|---|---|---|---|
| 000 | haiku | 50.0% | 語そのものを話題にした文 30 |
| **001** | **sonnet** | **100.0%** | — |
| **002** | **sonnet** | **100.0%** | — |
| 003 | haiku | 66.7% | `target_start` が違う 25 |
| 004 | haiku | 54.8% | `target_start` が違う 18 |
| 005 | haiku | 41.7% | `target_start` が違う 29 |

★**haiku は `text` を丸ごとカタカナで書く失敗もした**（001/002 で 214 件）。
ラティス整合は通ってしまう（UniDic はカタカナのエントリを持つ）ので、
専用のフィルタ（`is_broken`）を足して捕捉した。

★**sonnet が 100% を出せたのは、自分で `check()` を import して
全件検証したから**である。**検証手段を渡すと品質が跳ね上がる。**

## 設計意図

| 指示 | 理由 |
|---|---|
| 読みが曖昧な文を禁止 | 評価データなので、複数正解は測定を壊す（M3c で実際に起きた） |
| 周辺語を易しくする | 対象語の誤りと周辺語の誤りを混ぜない |
| 6 文 | 学習用（4 文）より多め。カテゴリ別に集計するため |
| 書けなくてよい | 歩留まりより物差しの正しさを優先する |
| ★`check()` を渡す | 自己検証できると採用率が 50% -> 100% になる（実測） |
| ★sonnet 以上 | haiku は `target_start` と言及文で落ちる（実測 42〜67%） |
