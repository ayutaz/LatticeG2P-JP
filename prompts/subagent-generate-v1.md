# サブエージェント生成プロンプト v1.2

`scripts/make_batches.py` が作った `data/batches/batch_NNN.jsonl` を
サブエージェントに渡すときのプロンプト。`NNN` の部分を差し替えて使う。

生成データの `prompt_version` に `subagent-v1` として記録される。

**v1.1 での変更**: 「漢数字を含めない」が対象語自体にも適用され、
`一`・`四十`・`二三十` のような漢数字の多音語がまるごと生成不可になっていた。
対象語に含まれる漢数字は許可するよう修正。

**v1.2 での変更**: 「少数派の読みを、その読みにならない文脈で使う」誤りが
実測で出たため、具体例つきの節を追加した（下記「★最も多い失敗」）。
ラティス整合フィルタでは検出できない種類の誤りで、そのまま学習させると
モデルに逆のことを教えてしまう。
**変更したらバージョンを上げること**（`docs/training.md` §10）。

日本語 G2P（漢字の読み推定）の学習データを生成するタスクです。

# 入力
`data/batches/batch_NNN.jsonl` を読んでください。
各行は `{"surface": 表記, "readings": [読み候補...], "pos_list": [品詞...]}` です。

# やること

各語について次の 2 段階で処理します。

## 段階 1: 読み候補の検証
`readings` の各読みが、**現代日本語でその表記の読みとして実在するか**を判定します。
- 実在しないもの、古語、単独では使われない語幹は除外する
- 例: 「先生」の「シェンシェイ」は中国語読みなので除外
- 例: 「一生」の「イッショ」は「一緒」との混同なので除外
- 判断に迷うものは除外してよい（質より確実性を優先）

## 段階 2: 例文の生成
検証を通った読みそれぞれについて、**4 文**ずつ生成します。

# 出力形式

`data/batches/batch_NNN.out.jsonl` に
1 行 1 文の JSONL で書いてください。各行は次の形式です。

```json
{"text": "今年の米は出来がいい", "reading": "コトシノコメワデキガイイ", "target_surface": "米", "target_reading": "コメ", "target_start": 3}
```

- `text`: 生成した日本語の文
- `reading`: **文全体**の読み（全角カタカナ）
- `target_surface`: 対象の表記（入力の surface をそのまま）
- `target_reading`: その文での対象語の読み
- `target_start`: `text` 中で対象語が始まる文字位置（0 始まり）

# ★読みの表記規則（最重要）

この規則を守らないとデータが使えません。

- すべて全角カタカナで書く
- **助詞の「は」は ワ** と書く（「私は」→ ワタシワ）
- **助詞の「へ」は エ** と書く（「家へ」→ イエエ）
- **助詞の「を」は ヲ** と書く（「米を」→ コメヲ）
- **長音は表記どおりに書く**（「東京」は トウキョウ。トーキョー とは書かない）
  （「学校」は ガッコウ、「先生」は センセイ、「注文」は チュウモン）
- 外来語の長音符はそのまま使う（「コーヒー」は コーヒー、「ラーメン」は ラーメン）
- 促音「ッ」、拗音「ャュョ」、撥音「ン」を省略しない
- 空白・句読点は読みに入れない（文には句読点を使ってよい）

# 文の要件

- 対象の表記が必ず指定の読みで読まれる自然な現代日本語の文にする
- 文の長さは 10〜40 文字程度
- 文体と話題を多様にする（すべて「〜です。」で終わらせない）
- 対象語の出現位置も多様にする（文頭・文中・文末）
- **算用数字を含めない**（1、２ など）
- **漢数字は、対象語に含まれる場合だけ許可**する
  （対象が「四十」なら「四十」は書いてよい。それ以外の場所には漢数字を書かない）
- **アルファベットを含めない**
- **固有名詞を含めない**（人名・地名・企業名・製品名）
- 記号は句読点のみ

# ★最も多い失敗：少数派の読みを、その読みにならない文脈で使う

このデータは「文脈によって漢字の読みが変わる」ことを学習させるためのものです。
**文脈的に誤った読みを書くと、モデルに逆のことを教えてしまいます。**

実際に出た誤りの例:

```
✗ その村は静かだ    → ソノソンワシズカダ     「村」単独は ムラ。ソン は熟語のみ
✗ 百粒の米が必要だ  → ヒャクツブノマイガ…    ここは コメ。マイ は「白米」等の熟語
```

**少数派の読み（音読み、連濁形など）を使うときは、その読みが確実にそうなる
複合語の中で使ってください。**

```
✓ 村 → ソン なら「農村」「漁村」「村長」の中で
✓ 米 → マイ なら「白米」「玄米」「新米」の中で
✓ 部屋 → ベヤ なら「大部屋」「相撲部屋」の中で
✓ 試合 → ジアイ なら「練習試合」「親善試合」の中で
```

単独で使うと訓読みになる漢字を、無理に音読みの文脈にしないでください。

**また、文脈で一意に決まらない読みは段階 1 で除外してください。**

```
✗ 六十 → ロクジッ / ロクジュッ   同じ文脈に両方当てはまる（自由変異）
✗ 唯一 → ユイツ / ユイイツ       どの文でも交換可能
✗ 最中 → サナカ / サイチュウ     常に両義
```

これらを入れると、同じ文脈に矛盾するラベルが付いてしまいます。

# 品質について

`reading` は機械的に検証されます。**文全体の読みを一字一句正確に**書いてください。
特に注意:
- 送り仮名や助詞を読み飛ばさない
- 連濁（「小包」→ コヅツミ）を正しく反映する
- 漢字の読みが文脈に合っているか確認する

自信が持てない文は書かないでください。数より正確さが重要です。

終わったら、書き出した文の数だけを報告してください。

## 設計意図

| 指示 | 理由 |
|---|---|
| カナ表記規則を明示 | 書かないと助詞の「は」が「ハ」で返る。規則は `docs/evaluation.md` §2 で実データから確定したもの |
| 読みの検証を先にさせる | 辞書の読み候補には実在しないものが混ざる（「先生→シェンシェイ」）。論文も同じ 2 段階構成 |
| 算用数字・英字・固有名詞を禁止 | 範囲外（`docs/pitfalls.md` R-04, R-05）。混入するとフィルタで落ちて歩留まりが下がる |
| 漢数字は対象語内でのみ許可 | v1 では一律禁止にした結果、`一`・`四十`・`二三十` のような漢数字の多音語が生成できなくなっていた（1 バッチで 5 語が全除外） |
| 「自信が持てない文は書かない」 | 読みの誤りはラティス整合フィルタで落ちるが、歩留まりが下がるだけで得はない |
| `target_start` を出させる | ただし回収側では信用せず表記から復元する（`data/batches.py`） |
